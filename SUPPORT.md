# Support

## How to file an issue

If you encounter a bug, have a feature request, or want to report
a problem, open a
[GitHub issue](https://github.com/sachncs/revex/issues).

Before filing, search existing issues to avoid duplicates. Include:

- A clear, descriptive title.
- Steps to reproduce (for bugs).
- Expected versus actual behavior.
- Environment details — OS, Node.js version, pnpm version, and the
  package versions from `pnpm list --depth=0` in the affected
  workspace.
- Relevant logs, screenshots, or a minimal repro. Reproductions
  that run against the published packages are the easiest to triage.

Bug reports use the `.github/ISSUE_TEMPLATE/bug.yml` template;
feature requests use `.github/ISSUE_TEMPLATE/feature_request.yml`.

## How to ask a question

For usage questions and ideas, open a
[GitHub discussion](https://github.com/sachncs/revex/discussions).
Use the `Q&A` category for "how do I…?" questions and the
`Ideas` category for feature brainstorming.

## Commercial support

Commercial support, training, and custom integration work are not
currently offered by the maintainers. If you need a partner, open
a discussion and we may be able to point you at a community
contributor.

## Code of Conduct

Everyone who interacts with the project in issues, discussions, or
pull requests is expected to follow the
[Code of Conduct](./CODE_OF_CONDUCT.md).
